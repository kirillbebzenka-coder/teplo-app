# TEPLO — курьерский кабинет, версия 66

Крупные спокойные карточки, чёрный фон, розово-фиолетовые акценты. Четыре раздела: Доставки (активные/завершённые), Заказы (свободная очередь), Заработок (сегодня/7 дней/всё время) и Профиль (смена, имя, уведомления, помощь).

Маршрут открывается из карточки. Крупные адреса, карта для каждой точки, звонок получателю, состав заказа, заработок, все остановки. Внизу одно действие по серверному статусу. Для двух заведений забор общий, с явным подтверждением получения во всех точках: независимый серверный учёт забора каждой точки пока отсутствует. Прежнее копирование адресов/телефона сохранено в дополнительных сведениях.

Действия используют прежние role-checked RPC: claim, courier_step, courier_shift. Изменения не включают реальные доставки и платежи. Клиент блокирует параллельные действия и offline-отправку; после ошибки/потери ответа повторно читает сервер. Финансовые суммы загружаются только для текущего курьера и отделены от ожидаемых; даты по Киеву. Активные доставки запрашиваются отдельно от истории, история имеет «Показать ещё». При одинаковых данных DOM не пересоздаётся каждые восемь секунд.

Кнопка проблемы вызывает teplo_courier_report_issue: подтверждённый курьер/админ, только собственный активный test job, выключенные реальные тарифы, 5–400 символов. SECURITY DEFINER нужен для ограниченной вставки в закрытую таблицу диспетчерских заметок; direct INSERT курьеру не выдаётся. EXECUTE для anon/PUBLIC отозван; RPC проверяет роль и назначение при каждом вызове. Блокировка job сериализует одинаковые сообщения; повтор той же причины в течение двух минут возвращает прежнюю запись. Статус доставки не меняется; автоматическое push-уведомление о ручной проблеме не обещается. Заметка доступна диспетчеру в «Проблемы и комментарии».

Предпросмотр: courier-preview.html (всегда без backend/auth), либо pilot-courier.html?preview=1. Вымышленные адреса/суммы, имитация действий заблокирована. courier-design.html показывает тот же интерфейс в iframe 390×844 для визуальной проверки. Предпросмотр отделён от реального кабинета и не является доказательством авторизации/доставки push.

Проверки: check-js, dispatcher-attention, checkout-network, courier-workspace, courier-controller (owner filters, no parallel writes, offline preservation, role revocation); SQL checkout-to-delivery, access-and-dispatch, role-rls, courier-issue с ROLLBACK. В браузере — вкладки, маршрут двух заведений/получателя, диалог проблемы, история, пустое состояние, мобильный viewport, отсутствие горизонтального переполнения. Вход в обновлённый кабинет на телефоне владельца и OS push-разрешения остаются физической приёмкой.
