# Время доставки и смысл слотов

## Первая тестовая политика
Теплодар: 20 минут. Дачи: 30 минут. Широкая Балка / Мирное / Пром: 40 минут. Это начальные настройки для проверки, а не измеренные нормативы или обещание реальной доставки. Ориентированы на забор из заведений Теплодара и включают дорогу и вручение после последней точки забора. Для заведений за пределами города потребуется отдельная проверка маршрута; расстояние и пробки автоматически пока не рассчитываются. Меню, готовность заведений и сбор по нескольким точкам учитываются отдельно. Приём двух разных доставок всё ещё ограничен серверным максимумом 2; это не рекомендация всегда брать две.

Покупатель выбирает населённый пункт из закрытого списка и вводит улицу/кооператив и дом. Сервер по коду населённого пункта выбирает одну из трёх зон; не доверяет минутам, переданным клиентом. Адрес хранит реальный выбранный населённый пункт, без прежнего принудительного префикса «Теплодар» для всех адресов. Повторное оформление с прежним request ID возвращает исходный заказ и не меняет зону/адрес. Старый RPC сохранён для совместимости. Сильные признаки населённого пункта в старых адресах распознаются автоматически; голая улица без населённого пункта не угадывается.

## Отсчёт
До забора показываем ориентир готовности, после его наступления — ожидание забора. Это не штрафной таймер доставки. На picked_up сервер фиксирует picked_up_at, delivery_minutes и абсолютный delivery_due_at. Для сборного заказа нажимать «Все точки забраны» можно после получения заказа во всех заведениях. Готовность первого заведения не запускает дорогу для всего заказа.

При перезагрузке читается тот же срок. Клиент сверяет время с сервером и считает прошедшее через монотонный performance.now: перевод часов телефона и throttling фоновой вкладки не должны перезапускать отсчёт. При возвращении выполняется синхронизация. За 5 минут — предупреждение; после срока — красная просрочка; delivered фиксирует результат по delivered_at. Не отменять автоматически заказ, не уменьшать начисление, не имитировать вручение.

Курьер может заполнить только неизвестную зону своего заказа. Диспетчер/админ может исправить зону до забора с причиной в teplo_dispatch_notes. После фиксации срока нельзя продлить его сменой зоны или готовности. Для старого уже забранного заказа без срока первое уточнение использует первоначальный picked_up_at, а не время уточнения. Исторические данные массово не переписываются.

Диспетчер видит те же сроки и просрочку. Фоновый контроль раз в минуту использует delivery_due_at вместо прежнего универсального часа; окончание окна забора не считается просрочкой уже забранного заказа. Push зависит от действующей подписки и системных разрешений; запись эскалации не доказывает показ на телефоне.

## Слоты: предложение для следующей настройки расписания
Для ресторанов рекомендуются 30-минутные окна забора/загрузки. Покупка «как можно скорее» должна попадать в ближайшее подходящее окно после готовности, без ожидания конца окна; срок дороги остаётся отдельным. Пример: готовность 18:10, окно забора 18:00–18:30, фактический забор 18:15 → срок по городу 18:35.

Начать с одного ресторанного маршрута на курьера на 30 минут. Вторую короткую доставку объединять только по пути и при совместимой готовности. Дальний маршрут занимает курьера и на обратную дорогу: нельзя считать его одной городской поездкой при планировании следующего окна. Сборный заказ из двух заведений — один получатель, но дополнительная нагрузка на забор. После 20–30 измеренных поездок уточнить нормы и вместимость по фактическому времени/зонам. Рабочие часы заведений и курьеров ещё не согласованы, поэтому существующие слоты, вместимости и автоматический подбор в этом выпуске не переписываются.

## Проверено
Node: регионы и неоднозначные названия улиц, все этапы таймера, warning/overdue, календарь, монотонные часы, различие окна забора и срока дороги. SQL ROLLBACK: 20/30/40 минут, полный путь заказа из двух заведений, правильный адрес, идемпотентность, отсутствие таймера на claim, неизменность при обновлении готовности/попытке продления, неизвестная зона, чужой курьер, закрытые anonymous grants, серверная эскалация и отсутствие дубля. Браузер: отсчёт секунд в мобильном предпросмотре, все этапы, оформление с выбором населённого пункта, отсутствие ложного сетевого сообщения при отсутствии входа. Фактические времена поездок ещё предстоит измерить.
